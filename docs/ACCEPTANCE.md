# Release acceptance

A passing unit test, build, screenshot or background process does not prove live integration success.
Do not publish v1.0.0 until the agreed feature set has passed with real Pack-In accounts and phones.

Required evidence:

1. HACS custom-repository recognition, download, normal config flow, reload/unload, amd64 and ARM64 dependency/runtime tests.
2. Premium phone approval, rejected/expired/replayed codes, wrong Pack, subscription expiry, revocation, renewal and account removal.
3. Bidirectional chore create/edit/delete/complete/reopen; assignments and recurring occurrences; concurrent edits and duplicate retries.
4. Bidirectional groceries including quantity, purchase, categories/claims, duplicate names and recovery.
5. Read-only calendar, all-day/timezone/DST/recurrence/overrides/cancellation, local calendar reads and open-view refresh.
6. Individually consented map positions, real observation timestamps, accuracy, stale/unavailable states and immediate consent removal.
7. Offline/restart/DO closure/token expiry/rate limits/server errors/key rotation/out-of-order/duplicate/stale revision recovery.
8. One Pack client, no full-data polling, batched location cadence, no entity-property HTTP or application heartbeat storm.
9. Cross-language canonical Android vectors, tampering/wrong keys/signatures/IDs/epochs, removed members and scoped server authorization.
10. Diagnostics/log/secret/dependency checks, additive migration/rollback and ordinary Android regression guards.

Record actual requests, messages, database operations, CPU and conditions.
Calculate household scale separately from measured production traffic and label estimates.
A real Premium account and a real second consenting member are needed for household privacy acceptance.
A blocked live test must remain BLOCKED. Do not substitute synthetic data or mark an unrun item PASS.
